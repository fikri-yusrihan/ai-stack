# Engineering Docs Workspace

- For a new project, read [Start Project](./skills/start-project/SKILL.md). It defines phase gates, owner decisions and agent assignments.
- To pick up a project, read [Resume Project](./skills/resume-project/SKILL.md) and inspect the existing artifacts.
- Read the [guidelines](./GUIDELINES.md) for writing, workspace layout and document status. The [numbered guide](./guide/README.md) explains each step.
- Before designing, writing or reviewing code, read the [architecture standard](./standards/architecture.md) and inspect the target repo's conventions.
- Use the [persona prompts](./agents/README.md) for research, design review, critique and approved implementation. The orchestrator writes the docs and brings unresolved decisions to the project owner.
- Keep facts and decisions traceable. Confirm authorization before commits, pushes, deployments or other changes to shared systems.
